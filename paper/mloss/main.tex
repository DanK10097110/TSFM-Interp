\title{\tool: Controlled, Causal and Confirmatory\\ Interpretability of Time-Series Foundation Models}

\author{\name Daniel Kushnir \AND \name Hao Wang}

\maketitle

\begin{abstract}%
\tool{} is an open-source Python toolkit that turns a list of time-series foundation model (TSFM)
checkpoints into a single self-contained interpretability report with one command. It compares models
with different architectures on a measured common time axis, validates every probe on a synthetic
benchmark with exact generative ground truth, defines concepts by their causal effect on the forecast
against matched random nulls, and tests exploratory claims once on a sealed held-out split. Every
reported number carries an evidence class and a plain-language explanation. The toolkit ships adapters
for TimesFM, the Chronos family, Sundial, Timer and Lag-Llama, a zero-code adapter for Hugging Face
checkpoints, a complete example run and a test suite of over two thousand tests. It is released under the
MIT license at \url{\repourl}.
\end{abstract}

\begin{keywords}
  interpretability, time-series foundation models, sparse autoencoders, causal intervention, open-source software
\end{keywords}

\section{Introduction}

Pretrained forecasters such as TimesFM \citep{das2024timesfm} and Chronos \citep{ansari2024chronos}
are used zero-shot, yet little is known about what they
compute. Interpretability libraries built for language models work on one model at a time, and three properties of
TSFMs make a direct transfer unreliable: tokens cover 1 to 96 time steps depending on the architecture, so positions
are not comparable across models; real series carry no labels for trend, seasonality or noise, so probes cannot be
checked; and the causal effects of internal features are small enough that an uncontrolled measurement yields a
confident false positive. \tool{} is a comparative tool built around these problems: its unit of analysis is a panel
of models on a shared benchmark, and its output is a report designed so that a newcomer can read it and an expert can audit it.

\section{Architecture}

The repository contains two separately installable packages (Figure~\ref{fig:arch}).
\texttt{tsfm\_benchmark} builds and validates corpora; \texttt{tsfm\_lens} analyzes models and renders the
report. Their dependencies overlap only in NumPy, SciPy and PyYAML, so the benchmark can be used on its own.

\paragraph{Benchmark.} Generators come in two labeled tiers: a synthetic tier that touches no real data and records
every generative component, and a real-derived tier with attributional ground truth. Samples pass a leakage audit
against real archives; dev and private splits use disjoint seeds, are hashed and can be re-minted as fresh epochs.
Structured corruptions and single-knob counterfactuals give perturbations with known effects.

\paragraph{Adapters and alignment.} An adapter exposes loading, prediction, the module and token time spans; its
capability tier is derived from the methods it implements, and stages needing a higher tier are skipped with the
reason rendered. A zero-code adapter measures token spans from impulse responses for Hugging Face checkpoints and
refuses rather than guesses. Tokens are overlap-pooled onto common time windows, verified per layer by an alignment
gate, so every cross-model statistic compares the same stretch of time.

\paragraph{Stages.} Nineteen stages produce evidence of increasing strength: behavioral (accuracy, calibration, cost),
descriptive (depth profiles, lenses), geometric (CKA, stitching gain over an input baseline), causal within-model
(corruption fingerprints, patching, head ablation) and concept-level. A sparse-autoencoder feature counts as causal
only if removing it changes a forecast channel more than a random direction of matched size on the same series, after
reach controls confirm the intervention lands; concepts are then matched across models on two levels, same inputs and
same effect on those inputs. Stage inputs are fingerprinted, so cached artifacts are reused only while valid.

\paragraph{Statistics and report.} Intervals resample series, not windows; a multiplicity ledger flags correction
families that cannot reach significance; and exploratory claims are frozen in a hash-pinned registry and tested once
on the sealed split. The output is one self-contained HTML file whose sections pose plain questions, whose figures each
carry an explanation of how to read them, and whose every claim states its evidence class and a generated caveat.

\section{Comparison with Existing Tools}

General interpretability libraries are single-model microscopes: they supply hooks, caching, patching and sparse
dictionaries, and leave the experimental design to the user. Recent TSFM studies train sparse autoencoders on one
model \citep{mishra2026dissecting,oublal2026timesae,divo2026zeitgeist}. \tool{} builds on the same primitives but
adds what a cross-architecture comparison needs to be trustworthy (Table~\ref{tab:tools}): a measured time axis,
known answers, matched nulls with reach controls, correction for multiple testing, one-shot confirmation and a
report that states the evidence behind every claim. It complements these libraries rather than replacing them.

\section{Usage, Quality and Availability}

After \texttt{pip install -e . \&\& pip install -e tsfm\_lens}, one command runs a full analysis
(\texttt{python run.py -{}-config configs/examples/large\_4model.yaml}); presets cover a CPU-only mock smoke test, a
single model and a pair. The repository includes a complete four-model example run with its report and per-stage
artifacts, and a ledger of every finding with its reproduction command. The code is MIT-licensed; over 2{,}100 tests
run in continuous integration against pinned and, weekly, latest dependencies, and each load-bearing assertion must
be shown to fail against a planted regression. Documentation covers installation, adding models and a report walkthrough. Code: \url{\repourl}.
