\section{Controls Change Conclusions}
\label{sec:controls}

How can a reader know that an interpretability system is better than a careful script that runs the same
methods? For a tool whose purpose is to find out what is true about models, one useful answer is a
record of cases in which the obvious analysis produced an answer, the answer was wrong, and a specific
control caught it. Table~\ref{tab:controls} lists fourteen such cases from the development of \tool{}. Each
row gives what the uncontrolled analysis reported, what the controlled analysis found and the control that
now runs by default. In every case the uncontrolled output was well-formed, plausible and, in several cases,
more interesting than the truth. None of them raised an error.

\paragraph{Three failure classes.} The cases fall into three classes, and each class maps onto a design
principle of Section~\ref{sec:principles}. \emph{Interventions that never landed} (rows 1--4) produce flat
curves, tables of zeros or perfectly matching numbers, which read as strong negative results. The remedy
(P3) costs almost nothing: patching a layer into itself must return exactly 0.0, patching another layer must
return a nonzero change, two unpatched predictions must be identical, and the input front end must behave
like the peers'. \emph{Nulls that were too weak} (rows 5--9) produce inflated positive results, and the
failure often looks like a success: 30 of 30 concepts transferring, 93\% of headline features ``explained''.
The remedy is a null matched on the right confound and measured on the same rows, bounded from both sides,
with the lower tail used for claims of difference. \emph{Metrics that did not measure what they were named
for} (rows 10--14) are caught only by validating the metric on a case whose answer is known (P1): an untrained
twin, a random rotation, a checkpoint whose spans are known, a replicate seed.

\paragraph{Smaller failures of the same kind.} The ledger records further cases of each class. A headline
result that an SAE reconstruction \emph{improves} on the clean forecast ($-0.346$ $\Delta$MASE) replicated in 1 of 5
seeds and was retracted (\fid{MN-16}). A layer-spacing rule rejected the top-scoring TimesFM layer and admitted
two below the mean (\fid{DE-08}). A sign convention applied to a distance channel generated the sentence
``decreases how much the forecast changes'' for every family, which is meaningless for a quantity that
cannot be negative (\fid{CA-10}). And a small grounded language model asked to narrate features produced a new
class of unsupported claim after each of four guard-strengthening passes; in the final pass 2 of the 4
summaries that passed every guard were wrong, while 6 of 6 deterministic sentences were correct
(\fid{MN-06}). \tool{} therefore composes every report sentence deterministically from measured values.

\paragraph{What this does and does not show.} Table~\ref{tab:controls} is not a benchmark in which \tool{}
beats a baseline on a metric. It is a set of counterexamples: for each row, a pipeline that applies the same
method without the control would have reported the uncontrolled result. We regard this as the strongest
evidence available that the controls are necessary. It is necessarily incomplete: the table can list only the
failures that were caught, and Section~\ref{sec:limitations} discusses what the controls cannot catch. Every
control in the table runs in the default configuration, and the project's verification standard
(\repo{CONTRIBUTING.md}) requires each new test's load-bearing assertion to be shown failing against a
deliberately planted regression before it is merged.
